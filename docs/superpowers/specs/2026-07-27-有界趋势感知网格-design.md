> 经 brainstorming + **三方交叉审核**（Claude 主导 + 2 个独立 Codex 评审：务实风控派 / 极简 MVP 派）收敛后的定稿。

## 一句话原则（三方最强共识）

> **信号可以简单，执行不能简单。** 分类器判错最多少赚；平仓链出错会爆仓。复杂度砍在"趋势判断"，保留在"退出执行"。

## v2 → v3 的精简（砍掉的过度工程）

三态分类器 / 置信度% / 权重双轴 → **砍**；band 四态状态机 + COOLDOWN → **砍成两态**；渐进减仓连续风险函数 → **本轮不做**；十几个 CLI 调参 / 样本外标定 / WebSocket / 监控面板 → **砍或延后**。

## 用户拍板（本次范围决策）

| 议题 | 决策 |
|------|------|
| 有界区间 band | **保留轻量 band**（两态 ACTIVE/FROZEN + 最小持久化），不追价重心 |
| 温和减仓 | **本轮不做**渐进阶梯减仓；趋势/突破时只"停止亏损侧加仓"，库存靠硬止损兜底（渐进减仓列第二期） |
| 交易所端兜底 | **本轮做**：交易所端整仓 reduce-only TPSL + `mass_cancel`；维持 $1600 库存上限 |
| 分类器 | 二态趋势门控（复用现有 ADX 迟滞），只用已收盘 K 线 |
| 硬止损 | 距强平价 **12%** 单一触发线（v2 的 8% 太晚）+ 两条执行路径（本地确认平仓 / 交易所端 TPSL）+ $1600 仓位上限。**非"三重独立兜底"，是一线两路一上限** |
| 杠杆 / 密度 | 维持 20x / 8 档 0.5%，代码不改 |
| 启用方式 | `--trend-aware` 显式启用，默认与今日实盘逐调用一致，完全非破坏 |

## SDK 能力核实（已确认可落地）

- `orders.mass_cancel(cancel_all=True)` ✅；`OrderType.TPSL` + `OrderTpslType.POSITION`（整仓）+ `stop_loss`(`OrderTpslTriggerParam`) + `OrderTriggerPriceType`(mark 触发) ✅。
- 纯 dead-man 心跳自动撤：SDK 未见明确接口，实现阶段查 REST 端点；无则以交易所端 POSITION TPSL 作为掉线主兜底。

## 数据流（`--trend-aware` 开时，每轮）

```
1) 【硬止损前置】先于任何 K 线 REST：
     查真实持仓 → 非零才读 get_liquidation_info
     距强平 < 12% 或 已 HALTED → _go_off_confirmed()（确认平仓，见 C3）
2) 拉【已收盘】K 线 → ADX(14) 迟滞门控 → GRID_OK / RISK_OFF
3) band 两态推进：mark 越界 → FROZEN（撤亏损侧单）；仓位归零+冷却 → 重建
4) 动作：
     GRID_OK + ACTIVE → band 内铺阶梯（band 与 levels 取窄者）
     RISK_OFF 或 FROZEN → 停止亏损侧新增报价（不砸仓、不主动减仓），盈利侧止盈单照常
```

`--trend-aware` 关闭时，`run_once` 完全走原有 `decide_mode` + 中性网格，**不调用任何新逻辑**。

## Component 1：二态趋势门控（`grid/regime.py`）

- 复用现有 `adx()` + `decide_mode` 的迟滞思路，**不新增三态/置信度/权重**。新增 `TrendGate`（`GRID_OK / RISK_OFF`），或直接复用 `GridMode`（NEUTRAL=GRID_OK，OFF=RISK_OFF）语义，避免引入新枚举。
- **只用已收盘 1H K 线**：分类前丢弃形成中的当前小时线（现每 30 秒读最新 candle 会用半根）。
- 阈值：`adx_off` 初值 **30**、`adx_resume` **25**（迟滞）；连续 2 根已收盘 K 线确认再切，避免抖动。
- `RISK_OFF` 动作 = **暂停所有非 reduce-only 新单**（ADX 无方向，不猜哪侧，直接停双边新增；盈利侧已有止盈单照常成交），**不因分类器信号直接砸仓**（误判只少赚）。band 层的 FROZEN 有方向（mark 越界知道方向），用 `blocked_side` 记录，见 C2。

## Component 2：轻量有界区间 band（两态 + 最小持久化）

- 进入 `ACTIVE` 时算一次半宽：`half = clamp(band_k × atr, min_half, ~5%)`，默认 `band_k=1.75`、`min_half` 保证每侧至少 `min_levels(默认4)` 格。band **固定，绝不跟随现价移动**。
- 两态：`ACTIVE`（正常铺）→ mark 越界 → `FROZEN`（立即撤被冻结侧全部挂单、停止该侧新增）。越界方向进入 `FROZEN` 时确定并**持久化为 `blocked_side`**（跌破下界→冻结 BUY，涨破上界→冻结 SELL）；否则价格回到 band 内或进程重启后无从判断该冻结哪侧。
- 重建：仅当**仓位归零 + 无非 reduce-only 挂单 + 连续 N 根已收盘 K 线重新满足 GRID_OK** 才用新价重建 band（冷却用计数器，不设 COOLDOWN 状态）；重建时清空 `blocked_side`。
- **最小持久化**：`data/grid_state.json`（不放会被轮转的 `logs/`），原子写，字段 `{band_low, band_high, frozen, blocked_side, halted}`。`connect()` 读回。文件缺失/损坏时：空仓且无挂单→允许新建；有仓或有挂单→**fail-closed**，禁止按现价重心。

## Component 3：硬止损（执行确认，最不可砍）

**触发**（每轮最先、先于 K 线 REST）：

- **先查真实持仓；仓位为零时 `get_liquidation_info` 返回 None 是正常**（空仓冷启动），不得据此冻结。仅"**有仓位但拿不到清算价**"才 fail-safe 冻结新增。（修正 v2 把两种 None 混淆的 bug）
- 距强平：多头 `(mark−liq)/mark < hard_stop_dist`，空头对称。默认 **12%**，可配 `--hard-stop-dist`。
- 权益回撤线（控最大亏损）本轮不单独做，列第二期。诚实描述：这是**一条触发线（距强平 12%）+ 两条执行路径（本地确认平仓 / 交易所端 TPSL）+ $1600 仓位上限**，不是三重独立兜底。

**执行链**（`_go_off()` → `_go_off_confirmed()`）：

1. 持久化 `halted=true`，从此禁止任何新开仓（人工复位前不自动恢复）。
2. **只撤非 reduce-only 的网格单**（先查开放订单，过滤掉 TPSL / reduce-only 单再批量撤）——**绝不能 `cancel_all=True`**，否则会把交易所端 POSITION TPSL 这个最后兜底一起撤掉，若随后本地 IOC 部分成交/进程崩溃就留下裸仓。
3. 读最新仓位 → 发对应数量 `reduce_only` 市价（IOC）。
4. 短暂等待后**重新读仓位**；仍非零则按剩余量重试，逐级放宽滑点但限最大。
5. 连续两次读仓位为零、且无非 reduce-only 残单，才报"已平"；**此时才撤掉 TPSL**。
6. 删除"必在交易所强平前发动"的绝对表述——没有系统能保证。

## Component 4：交易所端兜底（掉线保护，本轮 P0）

- 挂**整仓 reduce-only TPSL**：`OrderType.TPSL` + `OrderTpslType.POSITION` + `stop_loss`（触发价按距强平 ~12% 或更早，mark 触发）。机器人 / REST / launchd 故障时，它是唯一仍可能工作的退出器。
- **必须随库存动态维护，不能只挂一次**：首次成交后创建；此后**每次风险仓增加 / 清算价靠近，都要更新并确认 TPSL 处于 `UNTRIGGERED`**（否则库存从小长到 $1600 时清算价漂移，旧 TPSL 触发价可能落到新强平价之后而失效）。**TPSL 缺失 / 更新失败 / 未确认为 UNTRIGGERED 时，禁止继续新增风险仓。**
- **dead-man 心跳自动撤**：官方 REST 疑似有端点，但它同样撤"所有开放订单"（可能连 TPSL 一起撤）。**实现阶段必须在 testnet 验证 dead-man 与 TPSL 的共存行为**，未验证前不启用、不宣称是两层独立保护。
- 注意：交易所平台重启的 post-only 阶段 TPSL 可能不触发，故 **$1600 库存上限必须始终保留**。

## Component 5：订单安全语义（修正现有 bug）

- `place_limit_order` 增加 `reduce_only` 传参（现固定 False，`extended_client.py:223`）；所有退出/止盈单 `reduce_only=True`，防残单反手开仓。
- `_cancel()` 现**在撤单请求成功前就从内存删订单**（`grid_engine.py:225`）→ 撤单失败会留孤儿风险单。改为**确认撤单成功后再删**。
- `_handle_fills()` 现读了 `filled_qty` 却按整格数量翻单（`grid_engine.py:158`）→ 部分成交隐藏风险。改为按实际 `filled_qty` 生成退出单；`TREND/FROZEN` 下不得重新生成被冻结方向的订单、过期单不重挂风险侧。
- `_within_cap()` 现按"订单数 × 名义"估算（`grid_engine.py:191`）→ 改为按真实持仓 + 各挂单剩余量算最坏仓位。

## Component 6：监控适配（`tools/grid_monitor.py`，最小）

- 现仍用旧 `decide_mode`（`grid_monitor.py:28/68`）→ 启用新策略后形成盲区。
- 最小改动：直接读引擎写出的 `data/grid_state.json`，报告 `ACTIVE/FROZEN/HALTED`、持仓、距强平%、最近成功风险检查时间、平仓重试失败。**不重新实现分类器**，不做完整仪表盘。

## Component 7：配置、CLI 与非破坏回归

- **`GridConfig` 新增**（均带默认值）：`trend_aware(False) / band_k(1.75) / min_half / min_levels(4) / hard_stop_dist(0.12) / adx_off(30) / adx_resume(25) / confirm_bars(2) / recenter_bars / state_path(data/grid_state.json) / exchange_tpsl(True)`。
- **`run_grid.py` 新增 CLI**：`--trend-aware / --band-k / --hard-stop-dist`（其余用默认，避免参数爆炸）。
- **非破坏回归（硬性）**：`trend_aware=False` 时**不得**调用任何新逻辑，下单方向/数量/调用顺序与现状逐调用一致；不改写现有 `GridMode.OFF` 语义；**首次启用**显式处理账户已接管的旧挂单；launchd plist 无 `--trend-aware`，默认关闭不影响现有实盘。
