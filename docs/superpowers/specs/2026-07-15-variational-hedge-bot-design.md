# 设计文档：Variational 跨所对冲积分 BOT

- **日期**：2026-07-15
- **状态**：待评审
- **作者**：Claude Code + 用户

---

## 1. 目标与背景

### 1.1 核心目标

在 **Variational Omni** 平台上运行一个自动化 BOT，主要目的是**赚取积分（面向 $VAR 空投预期）**，次要目的是赚钱（可接受一定磨损）。

关键洞察：采用**跨所 delta 中性对冲**策略，在 Variational 与 **Extended** 两个都在进行积分/空投活动的永续 DEX 上同时开反向仓位，做到：

- **方向性风险被对冲**——市场涨跌不影响本金，磨损仅剩点差 + 手续费 + 资金费净额；
- **两条腿同时挖两个空投**——一份资金在 Variational 赚"持仓（OI）积分"，在 Extended 赚"成交量/金库积分"；
- **属于真实活动而非刷单**——两个平台各自承担真实市场风险、产生真实成交量，被判作弊风险低。

### 1.2 已确认的约束

| 项 | 决策 |
|---|---|
| 资金规模 | < $5,000（分两腿，每腿约 $2,000–2,500） |
| Variational 接入方式 | **逆向网页端私有 API**，实时开单（用户已接受 ToS/失效风险） |
| 对冲场所 | **Extended**（官方 Python SDK 成熟、主网真钱、空投预期强） |
| 对冲策略 | 跨所对冲，delta 中性 |
| 杠杆 | 低杠杆 1–2x |
| Extended 账户 | 用户将自行注册/入金/生成 API key（作为部署前置） |

### 1.3 Variational 积分机制（调研结论）

- 每周固定积分池（约 150,000），周五 0:00 UTC 结算上一周活动。
- 经验公式（社区逆向，非官方）：
  `个人积分 ≈ 池 × (个人成交量 + 9 × 个人持仓) ÷ (全网成交量 + 9 × 全网持仓)`
- **持有敞口（OI）每美元约为成交量的 9 倍积分** → 策略应以"开仓后长期持有"为主，交易越少越好。
- 冷门/RWA 市场有 2x 加成，大币种 1x。
- 老用户 +10% 加成；等级（30 天成交量）+0.5%~+5% 加成；推荐返 10%。
- 平台保留自行修改/作废积分的权利。

### 1.4 平台费用（调研结论）

- **Variational**：零交易手续费，靠点差（OLP）盈利；每笔存/取 $0.1；强平 0.5% 罚金。
- **Extended**：Maker 2bps / Taker 4bps，maker 有返佣；每小时资金费。

## 2. 策略设计

### 2.1 基本形态

1. 在 **Variational** 开 **多头** BTC-PERP，低杠杆，开仓后**持有**（吃 OI 积分为主）。
2. 在 **Extended** 开等名义价值 **空头** BTC-PERP，对冲方向风险。
3. 组合净 delta ≈ 0。市场涨跌两腿盈亏抵消。
4. 仅当净 delta 漂移超过阈值（如名义价值的 ±2%）才再平衡，最小化交易磨损。

> 方向可反转（Variational 空 / Extended 多），由资金费率决定：选择让**净资金费对我们有利**的方向。

### 2.2 标的选择

- 首版仅 **BTC-PERP**（两平台都有、流动性最好、点差最小）。
- 可选扩展 ETH-PERP。
- Variational 的"冷门市场 2x 加成"诱人，但对冲腿必须同标的存在，且冷门币点差大、磨损高——**留作后续增强**，首版不做。

### 2.3 磨损与收益模型

| 成本项 | 说明 |
|---|---|
| Variational 点差 | 开/平各吃一次点差（持有期间不产生） |
| Extended 手续费 | 2–4 bps × 成交量（尽量用 maker 挂单降成本） |
| 资金费净额 | 两腿资金费之差，可正可负——策略主动选择有利方向 |
| 存取费 | Variational $0.1/笔，可忽略 |

因策略"开仓即持有、极少交易"，主要成本是**开仓/平仓两次的点差与手续费**，加上**每周资金费净额**。目标是让资金费净额尽量覆盖磨损，积分/空投为纯增量。

## 3. 系统架构

### 3.1 组件划分

```
variational-hedge-bot/
├── config/                      # 配置（标的、杠杆、阈值、风控参数）
├── adapters/
│   ├── base.py                  # 交易所适配器抽象接口
│   ├── variational.py           # Variational 逆向私有 API 适配器
│   └── extended.py              # Extended 官方 SDK 适配器
├── engine/
│   ├── hedge_engine.py          # 对冲主循环：监控 delta、再平衡决策
│   ├── risk.py                  # 风控：回撤/保证金/单腿故障应急
│   └── funding.py               # 资金费率监控与方向选择
├── tracking/
│   ├── points.py                # 两边积分预估
│   └── pnl.py                   # 磨损/净收益核算
├── infra/
│   ├── logger.py                # 中文日志，输出 log/
│   ├── secrets.py               # 私钥/API key 环境变量加载
│   └── store.py                 # 状态持久化（仓位、成本累计）
├── tools/
│   └── recon/                   # Variational 接口侦察工具（阶段一）
├── tests/
└── main.py                      # 入口，编排各组件
```

### 3.2 适配器统一接口

所有交易所适配器实现同一抽象接口，engine 不感知具体平台：

- `get_market(symbol)` → 行情（bid/ask/mark/funding）
- `get_position(symbol)` → 当前仓位（方向、名义价值、保证金）
- `place_order(symbol, side, size, type, price)` → 下单
- `cancel_order(order_id)`
- `get_balance()` → 账户余额/保证金率

### 3.3 Variational 适配器（最大不确定项）

官方交易 API 未开放，需逆向网页端私有 client API：

- **阶段一（侦察，先做）**：用抓包工具（浏览器 DevTools / mitmproxy）+ 阅读前端 JS，摸清：
  - 私有端点路径与请求/响应格式；
  - 认证/签名方案（钱包签名？会话 token？签名消息结构）；
  - 下单/撤单/查仓的具体调用。
- **阶段二（实现）**：优先"**浏览器辅助获取会话凭证 + 复用签名逻辑**"，而非从零重写签名，降低工作量与失效风险。
- 只读行情用官方 `metadata/stats`（限速 10 req/10s）。

### 3.4 Extended 适配器

直接用官方 Python SDK：`X-Api-Key` 头 + StarkEx/SNIP12 签名。SDK 已封装下单/查仓/查行情，工作量小。

### 3.5 对冲主循环

```
每 N 秒：
  1. 拉取两腿仓位与行情
  2. 计算组合净 delta
  3. 若 |净 delta| > 阈值 → 生成再平衡订单（优先 maker 挂单）
  4. 检查风控（保证金率、回撤、单腿断连）
  5. 记录积分预估与磨损
```

## 4. 风控设计

| 风险 | 应对 |
|---|---|
| 单腿保证金不足被强平 | 监控两腿保证金率，低于阈值自动减仓/补充；预留保证金缓冲 |
| 一腿故障/断连 → 裸敞口 | 检测到单腿失败，立即在另一腿紧急平仓，回到无敞口状态 |
| Variational 接口失效（前端改版） | 心跳检测；失败告警；降级为只监控 + 通知人工 |
| 资金费率转为不利 | funding 模块监控，持续不利时收缩或反转方向 |
| 极端行情/点差骤增 | 暂停再平衡，避免高磨损交易 |
| 私钥/密钥安全 | 环境变量或本地加密，绝不入库、不写日志 |

---

## 5. 分阶段实现路线

- **阶段一：Variational 接口侦察**（关键前置）——摸清私有 API 与签名，产出可调用的最小下单/查仓 demo。
- **阶段二：Extended 适配器**——基于官方 SDK，跑通下单/查仓/查行情（用户注册好账户后）。
- **阶段三：对冲引擎 + 风控**——delta 监控、再平衡、单腿故障应急。
- **阶段四：追踪与调度**——积分/磨损核算、日志、长时运行稳定性。
- **阶段五：小额实盘验证**——极小仓位跑通全链路，再逐步放量。

## 6. 明确不做（YAGNI）

- 首版不做冷门币 2x 加成套利（点差高、对冲难）。
- 首版不接 Decibel/RiseX（Extended 已够；RiseX 仅测试网）。
- 不做 Web UI/仪表盘（CLI + 日志即可）。
- 不做多账户/女巫矩阵（合规风险高，且非本项目目标）。

## 7. 已知风险与诚实声明

1. **Variational 交易 API 官方未开放**，逆向其私有接口/签名**可能违反 ToS，且前端改版即可能失效**——全项目最大的技术与合规不确定性。
2. **< $5,000 分两腿**，积分池固定会稀释，预期收益中等偏小，主要价值在空投预期。
3. **积分条款**写明平台可自行修改/作废点数。
4. 经验积分公式为社区逆向，非官方，实际权重可能变化。
