# 设计：同所黄金基差对冲模块（XAU 多 / XAUT 空）

- 日期：2026-07-20
- 状态：已批准，待实现（由 Codex 实现，Claude 审校）
- 相关：`tools/hedge.py`（BTC 跨所对冲，本模块参照其结构但不改动它）

## 1. 目标与背景

在 **Variational 单所内**做一对黄金 delta 中性仓：**多 XAU + 空 XAUT**。
两条腿都在 Variational，目的是同一份资金吃双份 OI 积分，且方向风险互相对冲。

已核实事实（2026-07-20，`/metadata/supported_assets` 与 `/funding/v2`）：

| 标的 | 合约类型 `instrument_type` | funding_interval_s | predicted_funding_rate | 24h 量 | 现价 |
|---|---|---|---|---|---|
| XAU（Gold） | `perpetual_rwa_future` | 14400 | `0` | $125M | ~4016 |
| XAUT（Tether Gold） | `perpetual_future` | 14400 | `0.1095`（正） | $3.8M（薄） | ~4007 |

方向依据：Variational 资金费正 = 空头收。XAU funding=0（多头不付），XAUT funding 正（空头收）→
唯一正 carry 方向为 **多 XAU + 空 XAUT**。反向为负 carry，禁止。

## 2. 范围（YAGNI）

- 只做手动三件套：`status` / `open` / `close`，新建 `tools/hedge_gold.py`。
- 不做自动守护 / 再平衡（待积分机制验证后另议）。
- 不影响现有 BTC 跨所流程。

## 3. 架构与对现有代码的影响

### 3.1 新增
- `tools/hedge_gold.py`：独立 CLI，照搬 `tools/hedge.py` 的 `open/status/close` 结构，但**两腿都走 `VariationalClient.market_order`**（同所），不涉及 Extended。

### 3.2 唯一改动的现有文件：`adapters/variational_client.py`
- `_instrument()` 增加两个**带默认值**的可选参数，默认值 = 现状，保证 `hedge.py` 行为零变化（非破坏性）：
  ```python
  def _instrument(underlying, instrument_type="perpetual_future", funding_interval_s=3600):
  ```
  - XAU 调用：`_instrument("XAU", "perpetual_rwa_future", 14400)`
  - XAUT 调用：`_instrument("XAUT", "perpetual_future", 14400)`
- `request_quote` / `market_order` 需能把 `instrument_type`、`funding_interval_s` 透传到 `_instrument`。
- `settlement_asset` 维持 `"USDC"`（如实测非 USDC，实现时以 RFQ 报价返回为准修正）。

### 3.3 实盘逆向修正（2026-07-20，首次实跑发现，已修）
- **RWA 需要 `kind` 字段**：XAU（`perpetual_rwa_future`）的 instrument 必须带 `kind = asset_class`（黄金=`"commodity"`），
  与前端 `Wo()` 构造一致；缺失 → `HTTP 400: missing field kind`。`_instrument` 已加 `kind` 可选参数。
  RWA 的 instrument 标识不含 funding_interval（后端忽略）。
- **XAUT 的 `funding_interval_s` 恒为 3600**：instrument 标识 = `P-XAUT-USDC-<interval>`，只有 3600 被支持；
  用 supported_assets 里的结算周期 14400 → `HTTP 400: unsupported instrument`。同 BTC 既有陷阱。
- **数量精度**：XAU/XAUT `min_qty_tick=0.00001`、`min_qty=0.00003`（来自报价 `qty_limits`）。
  当前模块从报价按候选字段名找步长失败会回退 0.001（合法，$300 小单足够）；后续可改为读 `qty_limits.bid.min_qty_tick`。

## 4. 必须修复的隐藏 bug（关键前提）

`VariationalClient.get_position(underlying)` 现用**子串匹配**：`underlying.upper() in instrument.upper()`。
`"XAU"` 是 `"XAUT"` 的子串 → 查 XAU 会误命中 XAUT，导致净 delta 算错、close 平错腿。

要求：本模块取仓必须用**精确 underlying 匹配**。实现方式二选一（实现者定，需写测试）：
- 给 `get_position` / `get_liquidation_info` 增加精确匹配开关（默认保持旧行为，避免影响 BTC）；或
- 在 `hedge_gold.py` 内实现精确取仓辅助函数。

## 5. 方向、下单顺序、腿差保护

- 方向锁定：多 XAU + 空 XAUT（代码内硬编码，不接受反向）。
- delta 中性 = 等盎司：两腿均为每盎司≈$4000 合约 → **`qty_XAU == qty_XAUT`**（同一 qty 基准，避免两价微差残留敞口）。
- qty 计算：按目标名义 N 与基准价（用 XAU mark）算 `qty = round_down(N / price, step)`；两腿用同一 qty。
  下单精度 step 从 RFQ 报价返回字段取；取不到时用保守步长并在日志标注。
- 下单顺序：**先开薄腿 XAUT 空** → 读回实际成交 qty → 按同 qty 开 XAU 多。
- 腿差保护：第二腿失败 → 立即告警并尝试 `reduce_only` 回滚第一腿；绝不留单边裸仓。
- 安全闸：`MAX_NOTIONAL` 单腿名义硬顶（默认沿用 hedge.py 的 2000）；`open` 前校验当前无 XAU/XAUT 持仓；
  jurisdiction 403（`VariationalJurisdictionError`）→ 提示"需在放行 IP（Codex）执行"。

## 6. status 与 close

- `status`：精确取两腿仓 → 净 delta（`qty_XAU - qty_XAUT`，中性≈0，容差=1 个 step）、
  funding 视图（XAU=0 / XAUT 正）、`/points/summary`（total_points / rank）。
- `close`：两腿 `is_reduce_only=true` 平掉，**先平薄腿 XAUT** 再平 XAU。

## 7. 测试要求

- `_instrument` 参数化：默认参数产出与旧版完全一致（回归）；显式传参产出正确 XAU/XAUT 描述符。
- 精确取仓：构造同时含 XAU、XAUT 的持仓 mock，断言各自只取到自己那条，净 delta 正确。
- 下单顺序 / 腿差回滚：mock 第二腿失败，断言触发第一腿回滚。
- 方向守卫：断言模块不会构造出"空 XAU / 多 XAUT"的反向组合。
- 不得触碰 / 破坏 `hedge.py` 现有测试（BTC 流程回归全绿）。

## 8. 首次实跑（模块交付后，人工执行，走 Codex/放行 IP）

开 ~$300/腿，跑一个 4h funding 周期，记录：
1. `/points` 增量——**验证空腿是否独立累积 OI 积分**（结构 A 的成败假设）；
2. XAUT funding 实际到账折算（校准 0.1095 的真实口径）；
3. XAU/XAUT 基差漂移（RWA vs 代币，周末尤甚）。
据此决定是否放大。

## 9. 未决/风险

- 积分是否按净 OI 计（若是，双份积分不成立）——首仓验证前不放大。
- XAUT 盘薄，进出滑点为主要成本；PAXG 更薄，排除。
- XAU 为 RWA，休市/周末可能跳空，基差风险非零，非同标的完美对冲。
