# 网格收益放大：格距标度指数 α 的测量

**日期**：2026-08-06
**状态**：设计已确认，待实现
**背景**：实盘网格运行稳定后，收益绝对金额偏低，需确定放大路径

---

## 1. 问题

网格实盘（BTC-USD，Extended）运行稳定，但绝对收益偏低。用户目标为「比率和金额都要提高，但先查清漏损再放大」。

前置约束：**不追加本金**（权益 $974）。

---

## 2. 现状诊断

### 2.1 实际业绩

入金后 2.59 天（64 个采样点）：

| 指标 | 数值 |
|---|---|
| 权益 | 948.65 → 971.71（+$23.06）|
| 日均 | +$8.91/天 = 0.939%/天 |
| 期间最大回撤 | $6.92（0.71%）|
| 库存峰值 | $2,664 |

按引擎计数器窗口（17.01 小时）精确对账，当前配置的 run-rate 为 **$12.61/天 = 1.29%/天**，优于 2.59 天均值——说明近期调优有效。

### 2.2 收益归因（17 小时精确窗口）

```
毛价差收入        +10.784
手续费             +0.000   ← 300/300 笔全 maker，maker 费率为 0
资金费             -0.060   ← 24h 累计 -0.84bp
库存浮动盈亏       -1.786   ← 残差
─────────────────────────
实际权益变化       +8.938
```

交易所费率档位：`maker_fee_rate=0.0`，`taker_fee_rate=0.000225`。

**结论：不存在可修复的漏损。** 那 $1.79 残差是库存的市价重估——窗口内价格从 64005 涨到 64555（+0.86%），网格一路卖出、从 +$820 多头翻成 -$667 空头，逆势累积的浮亏。这是网格策略的固有敞口，占毛收入 17%，属健康范围。

执行层指标全部干净：0 手续费、0 拒单、0 补单失败、0 坏快照。

### 2.3 关键约束

- **maker 费率为 0**：加密格距的头号成本（手续费）不存在
- **unit 放大受本金卡死**：库存峰值已是权益的 2.7 倍；unit 提到 500 会到 8 倍杠杆并超出 `max-inv` 上限。以现有本金，unit 上限约 250
- **风险样本不足**：0.71% 回撤是在 ADX 21–27、全程 neutral 的温和行情里测得，样本中**没有单边趋势**，不可线性外推

## 3. 理论框架

把价格路径在格距 `s` 上的穿越次数记作 `N(s)`：

```
收益        ≈ N(s) × unit × s / 2
库存风险    ≈ (ΔP / s) × unit        （ΔP 为单边移动幅度）
```

设 `N(s) ∝ s^(-α)`，则：

```
收益      ∝ unit × s^(1-α)
库存风险  ∝ unit × s^(-1)
收益/风险 ∝ s^(2-α)
```

| α | 含义 | 结论 |
|---|---|---|
| = 2 | 标准布朗运动 | **中性**，收窄格距白干 |
| > 2 | 振荡衰减快于扩散标度 | 收窄有利（**趋势行情也落在这一档**）|
| < 2 | 振荡衰减慢于扩散标度 | 放宽有利 |

**修正（2026-08-06，实测）**：本文档初稿曾写「趋势中 H 升、α 降」，方向是错的。
强漂移合成路径实测 α = 2.39～2.95 并随漂移增强继续上升，因为趋势把振荡消灭得
比扩散标度更快。判读时必须同时看 α 与转折数绝对值——趋势下 α>2 但转折数趋近 0，
此时正确动作是不做网格（引擎 ADX 急停已覆盖），而非收窄格距。

**α 是本设计唯一要测的量。** 它对应 Hurst 指数（α = 1/H），是市场微观结构性质，比「日均收益」这类行情快照稳定得多。

### 3.1 为什么测 α 而不是测日收益

用户提出的质疑成立：任何「跑三天得出 spacing=X 时日赚 $Y」的结论都是那三天行情的函数，不可外推。

本设计的应对：**不测日收益，测标度指数**。α 会随 regime 变化（趋势中 α 升，见上方修正），但这恰恰是可用信息——引擎已有 ADX 与 trend-aware 分支可消费按 regime 分档的 α 表。

产出目标不是「一个永远最优的 spacing」（该物不存在），而是**一个能持续回答「当前 regime 下该用多宽」的测量器**。

### 3.2 负面结论同样有价值

若测得各 regime 下 α ≈ 2，结论为「收窄格距在数学上白干」，据此可停止在格距方向投入，转向加本金或多品种。这是可外推的、值钱的结论。

## 4. 数据源选型（探测实验结论）

设计中数据源经过三轮实测修正，记录证据以免重蹈覆辙。

### 4.1 mark price 不可用

```
90 次 @ 1s 轮询：200 响应 90/90，无 429，延迟中位 68ms
但只有 16 个不同取值（18%），变化间隔中位 5.01s
72 秒窗口逐笔总变差 0.1545%，同期 mark price 折算仅 0.0393%
```

**服务端 mark price 约 5 秒刷新一次，且总变差只有真实成交路径的 26%。** 标记价是指数价加基差平滑的产物，抹掉了约 74% 的可捕获波动。用它测 `N(s)` 会系统性低估约 4 倍。

**副产品结论**：引擎当前 2.5s 轮询已快于 mark price 刷新率，「提速到 1s」这条路径已被证伪，无需再测。

### 4.2 REST 成交接口不可用

```
第1轮: 50笔 跨度2.43min   20.6笔/min
第2轮: 50笔 跨度0.03min  1854笔/min  断档=True  ← 1.8 秒 50 笔，确认丢数据
第6轮: 50笔 跨度1.90min   26.4笔/min
```

`/info/markets/BTC-USD/trades` 硬顶 50 笔，`limit` 与 `endTime` 参数均被忽略（无历史分页）。成交呈突发式，爆发时任何轮询间隔都会丢数据——**而爆发正是价格快速移动、网格该成交的时刻**，丢在此处会让 `N(s)` 偏低且偏在最关键处。

### 4.3 采用：公开成交 WebSocket 流

```
72 秒收到 62 笔，唯一 id 62/62（零重复、零丢失）
成交间隔 中位 0.196s，最大 23.8s
速率 51.6 笔/分钟
逐笔总变差 $100.0 = 0.1545%
```

`wss://api.starknet.extended.exchange/stream.extended.exchange/v1/publicTrades/BTC-USD`，公开流无需认证。

**必须绕过 SDK 直连**：`x10.clients.stream.stream_client` 在 websockets 16.1 下已损坏——仍使用 14 版即改名为 `additional_headers` 的 `extra_headers` 参数。此问题不影响实盘（引擎仅走 REST）。

本机设有 HTTP 代理环境变量，连接时须显式 `proxy=None` 直连。

### 4.4 规模参照

按实测总变差，市场每日提供约 185% 的总变差，理论上限 `1.85 × 166 / 2 ≈ $154/天`，而实际到手 $12.6/天——**网格仅捕获约 8% 的可用波动**，其余发生在小于一格（$64）的微小波动中。

此数据不构成「收窄必赚」的证据（库存风险同步放大，中性与否仍取决于 α），但说明可捕获的波动确实存在，值得测量。

## 5. 设计

### 5.1 架构与边界

两个互相独立的部分，**均不接触实盘引擎**：

```
[采集器 trade_collector]  ──WebSocket长连接──> publicTrades/BTC-USD
   独立进程 / launchd 常驻（KeepAlive）              │
   引擎无需重启、无需改动                            ▼
                                        data/trades/YYYY-MM-DD.jsonl
                                                    │
[分析脚本 analyze_alpha]  ──离线读取───────────────┘
   现算 σ 定窗口，算振荡数，拟合局部 α(s)，按 ADX regime 分档
```

边界原则：采集器**只订阅公开行情**，不碰账户、不碰订单、不 import `grid_engine`。它挂掉实盘照跑，实盘挂了它照采。

### 5.2 组件

| 组件 | 职责 | 规模 |
|---|---|---|
| `tools/trade_collector.py` | 订阅公开成交流，逐笔落盘，断线重连 + REST 补洞 | ~120 行 |
| `data/trades/YYYY-MM-DD.jsonl` | `{"i": id, "T": ts_ms, "p": price, "q": qty, "S": side}` | ~4.5MB/天 |
| `tools/analyze_alpha.py` | 现算 σ 定窗口、算振荡数、拟合局部 α、regime 分档、输出报告 | ~90 行 |
| `~/Library/LaunchAgents/com.variational.trade-collector.plist` | 常驻托管（`KeepAlive`，区别于 monitor 的 `StartInterval`） | — |

### 5.3 核心算法

**度量必须是「振荡数」而非「格线穿越数」。这一条搞错整个项目作废。**

初稿曾定义为「把价格映射为对数格号 `k(t)`，统计 `k` 变化的总次数」。**该量实测在横跨 400 倍的 s 范围上恒等于 `α = 1.000`，对任何离散路径都一样，不携带任何信息。** 原因：它等于「离散路径总变差 ÷ s」，恒 ∝ 1/s。

物理上也讲不通——价格在某条格线附近抖动会反复穿越它，但挂在 `L(k+1)` 的卖单只成交一次；要再赚一次必须让价格**走满一整格**回到 `L(k)`。

正确定义：**振幅 ≥ s 的方向转折次数**（zigzag）。维护当前极值与方向，价格反向走满一格即记一次转折。实测验证（合成布朗路径，3 个种子）：局部 α = 1.952 / 2.068 / 2.028，且转折数与理论 `Tσ²/s²` 逐点吻合。

#### 扫描窗口相对 σ 自动确定

实测局部 α 随 `s/σ` 变化（σ = 每笔成交对数收益标准差）：

- `s/σ < 16`：采样相对格距太粗，α 被压低到 1.63，伪信号
- `16 ≤ s/σ ≤ 64`：α 收敛到 1.87～1.98，**可用区**
- `s/σ > 64`：转折数太少，噪声主导

因此窗口取 `[16σ, 64σ]`，σ 由分析脚本从数据现算，**不得写死绝对格距**。下界另受 tick 约束（每格至少 8 个 tick），取二者较大值。

按实测每笔平均移动约 $1.6（σ≈0.0031%）估算，窗口约 **0.05%–0.20%**，当前操作点 **0.0986% 正落在窗口中央**。

#### 不拟合单一全局 α

在 log-log 平面上取 5 点滑动窗口，报告局部斜率 `α(s)` 曲线。决策只看**操作点附近的局部 α**——我们要回答的是「从现在这个格距往宽还是往窄挪」，不需要一个全局常数。

按 ADX 分三档（`<20` / `20–30` / `>30`）各出一条曲线。ADX 由 `data/grid_monitor.jsonl` 按时间戳对齐（小时级足够，regime 本身是慢变量）。

### 5.3.1 结论的可执行范围

即使 α 指示应当收窄，实际能收到多窄另有一道硬约束：**`min_order_size = 0.0001 BTC`**。

维持库存风险不变的收窄方式是 `spacing 与 unit 同比缩小`，而 `qty = unit / price` 不得低于 0.0001 BTC。当前 `unit=166` 对应 `qty=0.00257 BTC`，距下限有 **25 倍余量**，即理论上 spacing 最细可收到 `0.0986% / 25 ≈ 0.004%`——但该值已低于上述 tick 下界，所以**真正的约束是 tick 而非最小下单量**，可收窄的极限约为 0.01%（即当前格距的 1/10）。

分析报告须同时输出「α 建议的 s」与「tick 允许的 s 下限」，取二者较大值作为可执行建议。

### 5.4 错误处理

- **断线**：指数退避重连（1s→2s→4s→…→60s 封顶），重连后立即用 REST `/trades` 拉最近 50 笔补洞
- **补洞失败或缺口过大**：写一条 `{"gap": true, "from": ts1, "to": ts2}` 标记记录。分析脚本遇到 gap 标记时**截断该段而非跨越拼接**——跨越缺口会凭空制造一次巨大跳变，直接污染 α
- **重复成交**：按交易所 `i` 去重（实测 id 唯一，62/62 无重复）
- **磁盘**：按天切文件；保留 30 天，超期仅提示不自动删（不自动删实盘相关数据）
- **时钟**：一律使用交易所时间戳 `T`，不使用本机时间

### 5.5 测试策略

三层验证，从合成数据一路验到实盘。**这是防止第三次翻车的全部保障。**

1. **合成布朗运动**：生成 drift=0 的路径，**3 个种子的局部 α 均值须落在 (1.75, 2.25)，最低 R² > 0.9**（实测 1.952 / 2.068 / 2.028，最低 R² 0.958）。此关不过则算法本身有误，不得继续
2. **合成趋势路径**：注入漂移 3e-6，**必须测出 α > 2.2**（实测 2.391）。注意方向——趋势使 α **上升**而非下降
3. **实盘证伪锚点**：用逐笔序列算 `N(0.0986%)` 换算成闭环率，**必须对上实盘实测的 ~4 闭环/小时**（基准取计数器窗口：67 闭环 / 17.01h，该段配置纯净）。对不上则存在系统性偏差，结论一律作废

第 3 条是唯一能证伪整套模型的检查点。注意它是拿实盘去**证伪**模型，而非拿实盘去**校准**模型——后者容易把错误糊过去。

### 5.6 明确不做（YAGNI）

- 不做订单队列模拟
- 不做影子撮合引擎
- 不做自动调参
- 不改实盘引擎任何代码

本轮只回答「α 是多少」，拿到数字再决定下一步动什么。

## 9. 实施期间的实测修正

实现过程中有四条结论推翻了本文档初稿的设计，记录于此。

### 9.1 度量必须是「振荡数」而非「穿越数」

初稿定义 `N(s)` 为格线穿越次数。**该量实测在横跨 400 倍的 s 范围上恒等于 α=1.000**，对任何离散路径都一样，不携带信息——它等于「离散路径总变差 ÷ s」。改为「振幅 ≥ s 的方向转折数」（zigzag）后，布朗路径实测 α=1.95/2.07/2.03，与理论 `Tσ²/s²` 逐点吻合。详见计划文档「关键设计约束」。

### 9.2 趋势使 α 上升而非下降

初稿写「趋势中 H 升、α 降」，方向错了。强漂移合成路径实测 α=2.39～2.95 并随漂移增强继续上升。

### 9.3 σ 必须只用段内收益

`analyze()` 初版把各段拼接后算 σ。段与段之间那对价格是跨越缺口的假收益，实测（15 段、段间跳变 0.2%）**σ 虚高 438%**，扫描窗口整体平移到把操作点排除在外。

值得注意的是同一份跨段拼接在两条路径上的危害差三个数量级：

| 路径 | 后果 |
|---|---|
| 振荡计数 | 每缺口 +1 次假转折（可忽略）|
| **σ 估计** | **虚高 438%，窗口平移，操作点出界** |

因为 σ 是方差——一次 0.2% 的跳变在一堆 3e-5 量级的收益里是巨大离群值，平方后完全主导估计。

### 9.4 缺口时间阈值 60 秒会误报，且代价极高

实测 3.7 小时内误报 12 次，采集器日志证明期间**连接零中断**，全部是真实市场静默。

误报不是「浪费一点数据」：宽格距上一次转折需要价格单向走完一整格再反转，耗时几分钟、天然跨越静默期，在那里切一刀会把真实转折劈成两半双双不计。实测这 12 次误报把操作点 α 从 **1.406 抬到 2.811**——跨过中性区两侧，导出完全相反的交易决策。

阈值改为 300 秒。它现在只兜底「连接活着但应用层不发数据」：断线与进程重启已由 `mark_discontinuity()` 显式标记，websockets 默认 `ping_interval=20/ping_timeout=20` 也会在 40 秒内把死连接转成重连。

### 9.5 公开成交流会补发 backlog

实测连上时补发**严格按笔数封顶、恒定 50 笔**（连续 4 次探测笔数方差为 0，时间跨度 3.6～30.3 秒剧烈波动）。进程重启后必须回灌历史 id 去重，否则这批已落盘成交会被重复写入。

## 10. 最终结论：本项目未产出可执行的参数建议

**2026-08-08 结项。没有找到值得调整的格距参数。**

### 10.1 α 框架的前提是错的

本文档的核心假设是「网格收益 ∝ 振荡转折数」，据此测标度指数 α 来决定格距。**实盘数据否定了这个假设**：

```
振荡转折数/2 = 1.39 闭环/小时   ← 比实盘还低
格线穿越数/2 = 7.67 闭环/小时
实盘实测      = 3.94 闭环/小时   ← 落在两者之间
```

实盘闭环率**高于**振荡数给出的上界，说明收益并不跟着振荡数走。α 这个量测得再准，也回答不了格距该怎么定。

证伪锚点（第 5.5 节第三层）起了作用，但它报告的原因不准：它说「模型被证伪」，实际被证伪的是它自己的上界公式 `N_osc/2`——该公式假设「每个闭环需要一上一下两次转折」，而真实情况是**一次反转在多格行程后会产生一批闭环**（下穿 5 格再上穿 5 格 = 2 个转折点、约 5 个闭环）。

### 10.2 「格距越宽越好」的推论同样不成立

发现 α 框架失效后，曾据「`格线穿越数 × s` 在 10 倍格距范围内近似常数」推出「收益与格距无关、风险 ∝ 1/s、故越宽越好」。这个推论也是错的：

- **证据是循环的**：`穿越数 × s` 数学上就是价格路径的总变差，对任何路径、任何格距都近似不变，是几何恒等式而非市场发现
- **两个独立模拟器给出不同的标度**：一个得 `收益 ∝ s^-0.63`，另一个得 `s^-0.04`；实盘闭环率夹在两者之间。分歧源于「某档成交后是否立即补回同向单」这一建模假设，实盘日志显示引擎会补回，但有 2.5 秒轮询延迟与队列摩擦，两个模型分别对应无摩擦与全摩擦两端
- **没有任何模型支持「调宽能增加收益」**，最乐观的也只是持平

### 10.3 结构性约束：格距不能单独调

`grid_engine.py` 的 `allowed()`（1405-1411 行）硬性限制**只有落在 band 内的档位才允许挂单**，band 外的已挂单还会被主动撤掉（1419-1428 行）。

当前参数存在精确耦合：

```
band 半宽 3.0000%（min_half_frac=0.03 楼板生效）
30 档 × 0.0986% 复利覆盖 3.0007%
```

单独调宽 spacing 会让外侧档位永久挂不出去：0.15% → 可用 19 档，0.40% → 可用 7 档。**任何格距实验都必须同步调整 `min_half_frac` / `levels`，是多参数改动。**

### 10.4 最大的数据空白

全部分析建立在 34.5 小时、ADX 10–23、价格区间仅 1.9% 的震荡样本上。唯一一次真实趋势（2026-07-21，ADX 峰值 46.3）发生在逐笔采集器上线之前，**没有留下 tick 数据**。

「宽格距在趋势行情中是否真的更安全」——这个风险管理上最该回答的问题，现有数据完全答不了。

### 10.5 后续处置

- 实盘参数维持 `spacing=0.0986%, unit=166, levels=30`，风控三层不变
- 逐笔采集器继续运行（成本 2.2 MB/天），**唯一目的是等一段 ADX>30 的趋势样本**
- `tools/verify_anchor.py` 的判据公式错误，已从定时任务中移除；定时快照改为监控实盘健康度与趋势样本捕获
- 若日后捕获到趋势样本，可用 `scratchpad` 中的网格成交模拟器重跑，那时才有条件回答 10.4 的问题

### 10.6 留下的可复用资产

- `grid/scaling.py`：振荡计数、σ 估计、自适应窗口、局部斜率拟合（243 个测试，含变异测试验证过的合成闸门）
- `tools/trade_collector.py`：逐笔采集器，缺口语义正确（断线/重启显式标记、backlog 去重）
- 网格成交模拟器（scratchpad）：按逐笔价格回放、维护每档挂单状态，可用于任何格距/档位参数的离线评估

**教训**：本项目两次得出结论、两次被自己的验证机制推翻。真正起作用的不是分析本身，而是「拿实盘去证伪模型」这道闸门，以及在改动实盘前坚持先量化。代价是三天工作没有产出参数建议，收获是排除了一整个方向。
