# 设计：对冲做市互锁与能力补齐

## 互锁是这套架构的命门

设计文档（2026-08-17）的原话：

> **最危险的组合是「做市在跑、对冲挂了」**——库存持续累积却无人对冲，
> 等人发现时可能已是大额裸仓。

在「只为积分」的模式下这更严重：闭环利润已被对冲抵消，**裸奔时没有任何收益
补偿风险**，纯粹是白担方向敞口。8/19 的 Lighter 就是这个形态，一晚上累到
−$3,943。

反向保险已经存在：对冲侧的 `max_primary_notional`（当前 $2,000）会拒绝跟随
异常膨胀的仓位。缺的是正向这一半。

## 关键决策

### 1. 互锁触发后「停止开新仓」而非「全部冻结」

这是本设计最重要的一条，直接来自 2026-08-10 的实盘教训（见
`grid-strategy` 记忆）：当时 ADX 熔断把两侧一起冻结，结果**挡住了新挂单，
却挡不住盘口上已存在的买单继续成交**，而成交后的卖出翻单被冻结阻止——
网格退化成单向抄底，库存被打成 $1,687 裸多头卡死 10.5 小时。

因此互锁的语义必须是**方向性**的：

- 禁止：会扩大当前敞口的挂单
- 允许：撤单、以及会缩小敞口的挂单（含成交后的闭环翻单）

**绝不能用「全局冻结」实现**，那会重演同一个故障。

### 2. 判活用心跳时间戳，不用进程存活

不去检查对冲进程的 PID，而是读 `data/lighter_hedge.jsonl` 的心跳时间戳。
理由：进程活着但卡在网络重试、或读取 Lighter 失败却仍在空转，都属于
「对冲实际未生效」，而 PID 检查看不出来。心跳带 `primary_read_ok` /
`hedge_read_ok` 字段，能反映真实工作状态。

超时阈值取 `3 × 对冲 interval`（当前 interval=30s，即 90 秒），与设计文档一致。

### 3. 心跳文件读取失败等同于对冲失效

文件不存在、解析失败、末行损坏，一律判定为失效并触发互锁。**不得因为
「读不到就当没问题」而放行**——那是 8/19 静默失效的同一个错误模式。

### 4. 未配置互锁时保持现状

互锁需显式启用（提供心跳路径与超时）。未配置时不做任何判定，行为与变更前
一致。这样 Extended 单独跑网格（不对冲）的场景不受影响。

但**一旦启用了对冲模式，互锁就应纳入 `grid-risk-selfcheck` 的依赖映射**，
缺失配置即拒绝启动——与其他风控层一视同仁。

### 5. `get_order_by_id` 两侧都要修

- **补齐 `LighterClient`**：让 `maker_first_hedge` 在 Lighter 侧可用
  （`grid-trading-window` 的计划离场依赖它）。
- **`hedge_engine` 改探测式**：即便补齐了 Lighter，`variational_client`
  仍未实现，且将来可能接入新适配器。直接调用未探测的能力是这次事故的同类
  错误，应一并修正。

缺失时的降级方向要谨慎：`maker_first_hedge` 读不到订单状态就无法知道成交了
多少，此时**不能盲目吃单**（会超额对冲），应撤单后重读仓位、按仓位差决定，
或直接放弃本轮 maker 优先、退化为直接吃单。具体取舍见 spec。

### 6. 对冲腿账户改为可配置

当前 plist 硬编码 `--account X10_HEDGE`，而该账户实测权益为 $0。
账户选择属于部署配置，不写死在代码里；本变更只保证参数可配并在启动摘要中
可见，**实际指向哪个账户由人工在验收后决定**（仓库约定不自动改 plist）。

## 实测数据（供调参参考，不在本变更优化）

对冲的 maker 成交率（958 样本 / 25 分钟 / 涨跌均覆盖）：

| 超时 | 对冲 maker 成交率 | 需吃单 |
|---|---|---|
| 15s | **10.8%** | 89.2% |
| 60s | 43.5% | 56.5% |
| 300s | 68.5% | 31.5% |

原因是结构性的：对冲方向天然逆势，挂单永远在价格跑离的那一侧。

**在「只为积分」的目标下，应选短超时**：优先保证对冲及时、敞口最小，
接受高 taker 比例。等待 maker 成交省下的手续费，会被暴露期的方向损失抵消
（参照 8/19 单小时 +$2,238 的行情，5 分钟可走 $186）。

## 不做

- 不优化对冲成本（规模与经济性另行决策）。
- 不改网格策略行为、不动任何风控阈值。
- 不自动修改 plist、不执行 launchctl。
