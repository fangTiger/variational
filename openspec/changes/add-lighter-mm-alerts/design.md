## Context

做市入口已经通过包装 `GridEngine.run_once()` 在每轮末尾写 JSONL，但当前只缓存
持仓数量，遗漏 `_inv()` 同次读取返回的标记价。主动告警已有成熟的对冲 JSONL
读取、有限数解析、三倍间隔门槛和未来时间容差，但对冲的“文件缺失即告警”不
适用于尚未部署的做市机器人。

## Goals / Non-Goals

**Goals:**

- 不增加交易所请求，用同一轮持仓与标记价生成可告警的库存名义额。
- 区分“未部署（文件不存在）”与“部署后异常（文件存在但无有效记录）”。
- 复用告警基础设施，同时保证做市与对冲冷却 key 完全隔离。

**Non-Goals:**

- 不改变网格引擎、适配器、对冲脚本或部署配置。
- 不新增进程探测、自动重启、交易或风控动作。
- 不为缺失价格推断、缓存或编造库存估值。

## Decisions

1. **复用 `_inv()` 返回值并缓存价格。** 包装器在已有结果中记录 size 与 mark；
   相比心跳时再次查询行情，这不会扩大网络失败面，也保证数量和价格来自同轮。
2. **以独立 `_collect_lighter_mm_alerts()` 隔离策略。** 通用 JSONL 读取和数值解析
   继续复用，但做市文件存在性在读取前显式判断；相比修改通用读取函数，这不会
   改变对冲的既有缺失语义。
3. **陈旧只看最新有效 JSON 对象。** 正数有限 `interval` 决定三倍门槛，其余
   回退 5 秒；超出既有 60 秒容差的未来时间戳直接走陈旧分支。
4. **连续失败统计最新尾部。** 从最新记录向前统计明确的 `success is False`，遇到
   成功或缺失字段即停止，使文案表达当前连续失败轮数，而不是历史最大值。
5. **库存只检查最新值。** 解析有限的 `inventory_usd` 与正数 `max_inv`，绝对值
   严格大于 90% 才告警；`null` 或损坏值跳过，避免未知数据制造误报。
6. **同步面板动作映射。** 每个新增 key 都登记中文处理动作，缺失、陈旧和连续
   失败按 critical 展示，库存逼近按 warning 展示，满足既有告警完整性契约。

## Risks / Trade-offs

- [告警检查间隔长于三轮失败窗口，机器人可能恢复后不再报警] → 心跳陈旧仍覆盖
  进程死亡；本变更遵循“连续失败”的当前状态语义，不扩展历史事件保留策略。
- [旧心跳没有 `interval`] → 以 5 秒回退，部署新代码后下一轮即自动恢复动态门槛。
- [标记价不可用导致库存盲区] → 明确写 `null`，不把未知风险伪装成安全的零库存。

## Migration Plan

先部署写入新字段的做市入口，再启用更新后的告警脚本。回滚时两个新增 JSON 字段
可被旧消费者忽略；移除做市告警接线即可恢复原行为，不需要迁移历史 JSONL。

## Open Questions

无。阈值、默认值、文件缺失语义和 key 前缀均由需求明确指定。
