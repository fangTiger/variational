## Context

统一面板的 provider 已把本地快照转换为 `SystemStatus`，渲染器按 `Metric` 列表展示卡片。网格已有未标基线的 `pnl_since_start`，对冲已有两腿当前权益，但数据契约没有可供总览统一汇总的累计收益字段。

## Goals / Non-Goals

**Goals:**
- 用显式基线计算累计总收益，并在卡片上展示基线日期。
- 明确区分网格当前浮动收益和累计总收益。
- 对冲总收益或当前持仓浮盈缺腿时拒绝计算，避免误导。
- 保持 provider 与渲染器解耦，并兼容所有既有 `SystemStatus` 构造调用。

**Non-Goals:**
- 不修改或生成任何基线、归因与心跳数据。
- 不使用权益差或单腿数据虚构对冲当前持仓浮盈。
- 不访问交易所、网络或修改交易逻辑。

## Decisions

### 1. `total_pnl` 追加在数据契约末尾
字段默认 `None`，并放在既有默认字段之后，避免旧的关键字和位置参数调用改变语义。provider 负责填值，注册表只负责汇总。

### 2. 基线必须同时具有有效权益和时间
累计收益的可解释性依赖基线日期。基线权益或 `ts` 任一无效，都不把它当作有效基线。网格可回退到现有 `pnl_since_start` 并标记“基线未知”；对冲没有等价可靠回退，直接显示 `—`。

### 3. 对冲沿用双腿完整性门槛
只有 `primary_collateral` 与 `hedge_equity` 都有效时才计算当前总权益和总收益。当前持仓浮盈独立使用心跳里的 `primary_unrealized + hedge_unrealized`；两者必须同时有效，缺一条腿就显示 `—`。该值衡量两所基差漂移，绝对值小于 5 美元视为对冲正常，小于 20 美元告警，更大标坏。

### 4. 汇总函数同时返回遗漏名单
注册表从 `SystemStatus.total_pnl` 产生合计值和未计入系统名；渲染器据此添加星号、说明性 `title` 和 tone class。这样渲染器不需要知道各 provider 的收益口径。

## Risks / Trade-offs

- 网格基线不可用时的回退值仍无法说明确切日期，因此卡片明确标为“基线未知”；总览仍可累加该兼容值，因为它与旧“自起始 PnL”口径相同。
- 归因卡片没有系统级总收益定义，会作为未计入项触发总览星号；这是显式展示数据覆盖范围，而不是静默假装完整。
