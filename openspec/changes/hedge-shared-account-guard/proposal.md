# Change: 对冲腿账户隔离改为显式知情 + 运行时校验

## Why

`run_lighter_hedge.py:274` 硬拒绝 `X10_GRID` 前缀，且拒绝任何与
`X10_GRID_VAULT_ID` 相同 vault 的账户。实测 `.env` 中
`X10_VAULT_ID` 与 `X10_GRID_VAULT_ID` **指向同一个 vault**，因此三个 Extended
账户里只有 `X10_HEDGE` 合法——而它余额为空，资金全在 `X10_GRID` 上。

该保护当初防的是「Extended 同时跑网格与对冲，两个策略仓位搅在一起」。但在
当前架构下 **Extended 不再跑网格、只做纯对冲腿**，前提已不成立：账户上不会有
网格持仓，对冲机器人镜像的就是它自己的仓位。

风险从「账户共用」转移到了「误启动网格进程」。因此应把静态黑名单换成
**显式知情声明 + 启动时实际状态校验**，与既有 `--waive-risk` 模式一致。

第一版把运行时状态校验写成「零持仓」，随后只补充了低于最小下单量的微仓
例外。这仍然选错了判据维度：`0.01972 BTC` 这类正常规模持仓可能正是 Extended
为抵消 Lighter primary 腿而建立的合法对冲仓。若一律要求 Extended 零仓，
对冲腿只要成功工作过就无法重启，人工平仓期间反而会让 primary 库存裸露。

这次事故必须保留的教训是：普通网格挂单才是网格活动的明确证据；持仓本身不是。
持仓门禁应判断两腿是否构成近似反向的合法对冲，并仅拒绝无法由 Lighter 持仓
解释的 Extended 残留。低于最小下单量的不可交易微仓仍需保留例外，避免再次
形成「必须启动才能归零、必须归零才能启动」的闭环。

## What Changes

- 新增显式开关，允许对冲腿使用与网格相同的账户；**默认关闭**，不声明时
  维持现有拒绝行为。
- 声明后仍须通过运行时校验：目标账户**无普通网格挂单**；Lighter primary
  与 Extended hedge 持仓近似互为反向，净敞口不得超过单腿数量乘以既有
  `rebalance_threshold` 比例。
- 默认容差比例复用既有 `--rebalance-threshold=0.02`，不新增、不硬编码另一套
  风控魔数，使启动判据与引擎运行后的再平衡判据保持一致。
- Extended 有仓而 Lighter 无法解释、两侧同向、任一侧读取失败时保守拒绝；
  错误信息给出两侧数量、净敞口与容差。
- Extended 不可交易微仓继续按上一轮修复放行。最小下单量由真实适配器市场
  元数据提供；查询失败时使用保守极小回退阈值并记录日志。
- 启动摘要标注该账户为共用模式，使其在日志中可见。

## Capabilities

### New Capabilities

- `hedge-shared-account-guard`: 定义共用账户的显式声明、启动时状态校验、
  拒绝条件与可观测性。

### Modified Capabilities

无。未声明开关时账户隔离行为完全不变。

## Impact

- 修改 `tools/run_lighter_hedge.py`：运行时独立读取两腿持仓并校验净敞口；
  Lighter 使用默认只读客户端，不启用交易能力。
- 修改 `adapters/extended_client.py`：提供不按标的过滤的账户级持仓与挂单读取，
  并公开按市场查询最小下单量的接口。
- 新增无网络测试，失败路径优先。
- **不修改** plist；账户切换由人工在验收后配置。
- 不改动任何风控阈值与对冲算法。
