# Design: Variational Swaps 接入与同所 carry 对冲

> 本文件已按 2026-09-04 两轮独立评审（Codex + Claude agent）与作者复核结论修订。
> 修订要点：推翻原 D2（保证金垫错了腿）、下调收益论证强度、取证任务前置。

## 一、实测事实（2026-09-04，经私有 API 实跑确认）

### 1.2 instrument 构造（实跑验证）

```
POST /quotes/indicative
{"instrument": {"underlying":"XAUS", "instrument_type":"swap",
                "settlement_asset":"USDC", "kind":"commodity",
                "funding_interval_s": 0}, "qty":"0.001"}
```

- `funding_interval_s=3600` → `HTTP 400 unsupported instrument: C-CMD-XAUS-USDC-3600`
- 缺 `kind` → `HTTP 400 missing field kind`
- `_resolve_instrument_params`（`adapters/variational_client.py:598`）对 XAUS

- `_instrument`（`:507`）的 `funding_interval_s` 默认值 3600 本身就是非法值，

### 1.3 资金费

Swap 走独立端点，`/funding/v2` 显式拒绝：
`funding info is not available for swap markets on this endpoint; use GET /funding/swap`

| 市场 | 多头年化 | 空头年化 |
|---|---|---|
| XAUS | -5.72% | +2.50% |
| XAGS | -5.63% | +2.40% |
| US500S / US100S | -4.65% | +2.65% |

- 每日 21:05Z 结算一次。符号约定：负 = 该方向付款，正 = 该方向收款。
- 中点 3.6~4.1% ≈ SOFR，与官方「4.5% all-in carry」口径吻合。
- **多日计提（×3）规则未被证实**：US500S 周五 `-0.1395 = 3 × -0.0465` 成立，
  但 XAUS 周五 `-0.057214` 与周三 `-0.056914` 都不是 3 倍。原假设「金属为周三」
  被实测否定。**禁止用「幅度约为 3 倍」的启发式判定多日计提**——那会在 OLP 真的
  把费率提到 3 倍时把告警吞掉。改用 `apply_time` 日历天数差判定，并以
  `/transfers` 实际扣款对账。

### 1.4 资金费单位口径（结论成立，证据链有缺口）

`tracking/monitor.py:7` 原假设 `predicted_funding_rate` 是「百分比 / 结算周期」。
经全量 1043 条 `/transfers`（535 条资金费）复核，**该值实为年化小数**，
单期费率 = 年化值 ÷ 每年周期数（365 天基准）：

- BTC 2026-09-04T08:00：`rate=0.0000685680365296804`、仓位 `+0.047801`、
  扣款 `-0.264342 USDC` → `扣款 = 费率 × 名义` 精确成立，隐含价 $80,655。
- `rate × (365d / interval)` 还原为干净 6 位小数：BTC(8h) 147/150、
  4h 市场 231/231、其余 154/154。
- **强旁证**：多个市场的年化上限恒为 `0.109500`
  （8h 市场 `0.0001 × 1095` = 4h 市场 `0.00005 × 2190`）——同一个费率帽在两种
  周期下折算成同一个年化数，只有在「值是年化」的假设下才成立。
- 360 天基准算不出干净值；「日利率 ÷ 3」也不干净。

**证据链的三个缺口（必须在上钱前闭合）**：

1. 证据来自 `/transfers.funding_rate`（已结算单期值），结论要用在
   `/funding/v2.predicted_funding_rate`（另一端点的另一字段）上。这一跳靠
   「数量级相近」补的，不是证明。**补法零成本**：记录某 `next_funding_time` 前的
   predicted 值，结算后取对应 `/transfers` 记录，断言
   `settled_rate == predicted / periods_per_year`。
2. **口径变过**：唯一 3 条不干净的记录集中在 2025-12-20/21，说明平台在某时点改成
   报年化。跨 2026 年初的历史回算不能用同一公式。
3. **只修了一条腿**：`tracking/monitor.py:52 compute_funding_view` 同时假设
   Extended 侧是「小数 / 1 小时」，同样从未校准。按新口径重算
   Variational BTC = 6.78%/年、Extended ≈ 11.4%/年，
   **现有 BTC 结构的推荐方向会翻转**（原「Variational 做空」→「Variational 做多」）。
   调用点：`tools/hedge.py:74`、`tracking/track_equity_util.py:33`。
   这是会真花钱的疏漏，独立列为 P0 任务。

### 1.5 保证金结构（关键，原 D2 在此出错）

同名义（qty=1，名义 ≈ $4470）实测 `/quotes/indicative`：

| 腿 | IM | MM | `margin_mode` | 多头强平 | 空头强平 |
|---|---|---|---|---|---|
| XAUS swap | 5.000% | 2.5% | **isolated** | -2.56% | +2.44% |
| XAU perp | 5.000% | 2.5% | **字段缺失（全仓）** | -17.90% | +17.03% |

- XAUS 的强平距离在 qty 从 0.001 放大到 1 时**完全不变** → isolated 桶就是名义的
  5%，账户其余权益不支撑它。理论值 `(5%-2.5%)/(1-2.5%) = 2.564%` 与 API 返回的
  `estimated_liquidation_price_ask = 4351.88` 精确吻合。
- XAU 永续同名义有 ±17%，且 qty=0.001 时返回的强平价荒谬地大 → 它吃整个账户权益。
- **推论：脆弱的是 swap 腿，不是永续腿。** 原 D2「垫厚永续腿」在经济上接近空操作。
- `liquidation_penalty = 0.1`、`auto_liquidation = true`。

**保证金可配置性（0 号阻断项，已找到机制、数值待实测澄清）**：

- `POST /settlement_pools/leverage {"assets":[...]}` 返回每资产按名义分档的平台下限。
  XAUS 在 0–2M 档为 `min_im 0.10 / min_mm 0.05`；XAU 在 0–5000 档为 `0.02 / 0.01`。
- `/settlement_pools/details` 显示我方 pool 的 `asset_params` 已对 **BTC 设 IM 2.5%、
  XAUT 设 2.857%**，XAUS/XAU 无覆盖。→ **按资产配置 IM 的能力确实存在且已在使用**。
- **未解矛盾**：XAUS 平台下限写着 IM 10%（对应 5.26% 强平空间），报价却按 5%/2.5%
  返回（2.56% 空间）。两者对不上，**在实测澄清前不得据任一数值定 spec**。

### 1.6 成本模型（已修正，原 9bp 为重复计数）

**点差（实测，qty=0.224 ≈ $1000/腿）**：XAUS 完整点差 1.353bp、XAU 永续 3.087bp；
`futures_taker_fee = 0`。两个市场的 `mark_price` 精确等于盘口中点，故公允价即中点。

**一条腿开+平只跨一次完整点差**（买 ask、卖 bid），不是两次。
故双腿一次完整往返 = `1.353 + 3.087 = 4.44bp`。
原 design 写的 9bp 是把每腿算了两遍，**已作废**。规划口径取 **6bp**
（4.44bp 实测 + 1.5bp 滑点缓冲），并要求探针仓实测 p90 校准。

**两腿计息节奏不同，不能对净 carry 统一乘 5/7**：
- 永续腿（收入）4h 连续计提 → 持仓窗口 118.5h/168h = **0.705**
- swap 腿（成本）每日 21:05Z 离散计提 → 周末平仓下只承担周一~周四 4 次 = **4/7 = 0.571**

正确公式：`R = f_perp × 0.705 − f_swap × (4/7) − 52c`
（错误写法：`R = (f_perp − f_swap) × 0.714 − 52c`）

**跳过的成本比例（42.9%）大于跳过的收入比例（29.5%）** → 周末平仓在费率结构上部分有利。

**修正后的盈亏平衡**（f_swap = 5.7214%）：

| 往返成本 | 年化成本 | 盈亏平衡 f_perp | 当前 f_perp≈9.94% 的 R |
|---|---|---|---|
| 4.44bp（实测） | 2.31% | **7.92%** | +1.42%/年 |
| 6bp（建议规划口径） | 3.12% | **9.06%** | +0.62%/年 |
| 不平仓持有 | ~0.24% | 5.96% | **+4.22%/年** |

**周末平仓 vs 持有相差约 6 倍收益（$6/年 vs $40/年，$1000/腿）——
政策选择比阈值调优重要一个数量级。**

### 1.6b 基差（原提案完全缺失的成本项）

实测 XAU `price` 4438.64 vs XAUS `price` 4435.04 → **永续高 8.12bp**；
两者 `index_price` 本身也差 **2.23bp**（4436.03 vs 4435.04）。
**这两条腿不是同一参考价的 delta-1 对冲。**

每周平仓一次会把基差波动**变成已实现盈亏**：单周期损益含 `−Δ(XAU − XAUS)`。
若每次往返基差漂移 ±5bp，年化即 ±2.6%——**与整个净 carry 同量级，比点差成本还大**。
持有过周末不消除基差风险，但把 52 次已实现基差噪声降为约 4 次。

### 1.6c 交易时段（禁止任何固定时钟假设）

XAUS 实测 `trading_sessions`：
```
open 2026-09-02T22:00Z → close 2026-09-03T21:00Z   (23.0h)
open 2026-09-03T22:00Z → close 2026-09-04T21:00Z   (23.0h)
open 2026-09-06T22:00Z → close 2026-09-07T18:30Z   (20.5h)  ← 劳动节，18:30 收市
```
- 常规：每日 21:00~22:00Z 休市 1 小时；**周五 21:00Z ~ 周日 22:00Z 休市 49 小时**。
- **但下周一 09-07 是 18:30Z 收市，不是 21:00Z**。市场上线仅 5 天，交易日历已不规则。
- 更麻烦：当天 **21:05Z 的资金费计提落在收市之后**，谁被计费、按几天计，完全未知。
- **结论：必须解析 `trading_sessions`，禁止写死 21:00Z。**

### 1.6d 【最高优先级未决问题】永续资金费是否存在 +10.95%/年 硬顶

对账户全部 536 条已结算资金费按**顶层** `funding_interval_s` 折算年化后统计：

| 合约类型 | 观测数 | 最大年化 | 正好 = 10.95% | **超过 10.95%** |
|---|---|---|---|---|
| `perpetual_future`（15 个标的合计） | **528** | **10.950%** | 204 | **0** |
| `perpetual_rwa_future`（SNDK） | 8 | **48.789%** | 0 | **6** |

`+10.95%/年 = 0.0001/8h = 0.00005/4h`，即行业标准基准资金费率。
**528 条观测 0 条突破、204 条正好压线 —— 这是硬帽，不是巧合。**

- **若 XAU 也在此帽下** → 最大净 carry 恒为 `10.95 − 5.72 = 5.23%/年`，
  而周末平仓政策的盈亏平衡 f_perp 是 7.92~9.06% →
  **数学上不可能盈利，提案当场终止。**
- **但 XAU 是 `perpetual_rwa_future`**，与 XAUT/PAXG（`perpetual_future`）不同类；
  同为 RWA 的 SNDK 已印到 +48.79%（8 条中 6 条突破帽子）。
  → RWA 类**大概率**不受此限，18.87% 的读数可信。
- **然而我们对 XAU 本身的账户内历史样本数 = 0。**
  XAUT/PAXG 虽是黄金代理，但它们被封顶而 XAU 没有，**在上行方向是错误代理**。

**这是全局信息量/成本比最高的一步：每小时一次 GET，一周内可出结论，
且可能单方面终结整个提案。必须排在任何编码与开仓之前。**

### 1.7 收益口径的诚实表述

**+13.15% 是瞬时年化名义收益率，不是预期收益，也不是账户 ROE。**

- 两腿均按 1x 名义备资金时，总资金口径毛 ROE ≈ 6.6%。
- 若为覆盖周末跳空把 swap 腿 IM 提到 10~15%，资金占用翻倍，ROE 进一步稀释到 6~8%。
- 收益支点（XAU 永续费率）波动剧烈：09-04 11:35Z 实测已从 0.1887 变为 0.200883，
  半天动 1.2 个百分点。账户历史上黄金类永续**已实现**年化区间为
  XAUT `-18.58% ~ +10.95%`、PAXG `-35.70% ~ +10.95%`——**经常深度转负**。
  若做空永续时费率跑到 -20%，净 carry = **-25.7%/年**，且可能撞上休市窗口出不来。
- **自反性**：swap 费率是 OLP 定的类 SOFR 固定价（不随供需走），永续的 20% 是供需价。
  这笔套利本身在压低永续费率，XAUS 多头 OI $24.8M vs 空头 $9.0M 已显示单边拥挤。
- **规模现实**：账户可投规模处于「单腿名义约等于账户权益」的量级，且已被一个 BTC 空腿部分占用。即便 13%/年成立，
  可投规模下绝对收益是**每天 $1 量级**，换来的是一个「49 小时不可交易窗口 +
  isolated 2.56% 强平线 + 单一对手方 + 上线 4 天新品」的结构。风险收益比必须
  在决策时被诚实计入。

### 1.8 平台与对手方风险

- XAUS 是 **RFQ 无订单簿、单一 OLP 对手方**（`counterparty` 全账户同一 UUID）。
- `is_close_only_mode` 字段存在 → 平台可随时把市场切为只减仓。
- `basis: "rates"` 的费率由 OLP 单方面每日设定（已观察到 -0.056914 → -0.057214 变动）。
- ADL / 对手方清算：OLP 自身承压时可强制关闭用户仓位，**用户保证金充足也不能豁免**。
- 周日 22:00Z 开市那一刻，若 OLP 不报价或报价极宽，**既平不掉也补不了保证金**。
  这与 1.5 的 isolated 2.56% 叠加，构成「跳空 + 无法退出 + 单腿爆仓」的复合风险。
- 上线仅 4 天，**没有任何周末开市重定价的历史样本**。

## 二、候选结构与取舍

| 结构 | 瞬时净 carry | 裁决 |
|---|---|---|
| **A. 多 XAUS + 空 XAU** | +13.15%/年 | 本变更唯一实现目标 |
| B. 空 XAGS + 多 XAG | +2.40%/年 | 收益薄，**本变更不实现，不做配置化预留** |

## 三、设计决策（修订版）

### D1. v1 方向写死，不自动翻向
v1 只做「多 XAUS + 空 XAU」。净 carry 转负时**退出**，不自动开反向仓。
理由：反向组合（空 XAUS + 多 XAU）的 carry 结构完全不同，需独立论证；
自动翻向会在费率震荡时反复吃 9bp 往返成本。

### D2（重写）. 周末不持仓；持仓过周末需单独论证
**原方案「垫厚永续腿保证金过周末」作废——它保护了错误的腿（见 §1.5）。**

v1 默认：**周五休市前平掉两腿**。
- 只跑 5 天：`13.15% × 5/7 ≈ 9.39%`；每周往返 9bp ≈ `4.68%/年`；**净剩约 4.7%/年**。
- 原提案否决方案 (a) 时算漏了这笔账——它仍是正收益。

若未来要持仓过周末，前置条件（全部满足才可）：
1. §1.5 的 XAUS 实际 IM 下限矛盾已被实测澄清；
2. 已验证可通过 `asset_params` 把 XAUS 的 IM 提高到覆盖周末跳空 99 分位的水位
   （黄金周末跳空 99 分位约 2~3%，尾部 5%+ → 5% IM 明显不够，需 10% 覆盖 99 分位、
   15% 覆盖尾部），并已把由此产生的 ROE 稀释写入收益模型；
3. 已完整走过至少一次探针仓规模的周末，且开市后 OLP 报价正常；
4. 策略进程常驻放行 IP，风控动作无需人工介入（见 D4）。

### D2b. 周末政策保持 weekly_flat，但收益模型必须并列算出 hold_through

原 D2 只写了 isolated 的负面。**它有一个被忽略的正面推论**：
XAUS 多头强平在 −2.561% 的同一时刻，XAU 空腿浮盈 +2.561%，两者高度对冲。
isolated 桶 = 名义 5%，触发时余 MM 2.5%，`liquidation_penalty = 0.1`
→ 净实际损伤约 **1% 名义量级**，且留下的是一条 **24/7 可随时平掉**的空腿。
所以「单腿爆仓后另一腿也平不掉」这个最坏状态**并不成立**。

即：周末风险不是「灾难 vs 4.7%/年」，而是
**「低概率、约 1% 名义的有界止损」vs「确定的 2.3~4.7%/年往返成本 + 52 次已实现基差噪声」**。

**但在以下三项有结论前，policy 一律保持 `weekly_flat`**：
1. §1.5 的 XAUS 实际 IM 下限矛盾（`min_im 0.10` vs 报价 0.05）
2. **swap 多日计提方向**（下节 D2c）——若周一追补 Sat/Sun，持有反而更贵，结论翻转
3. 进程能否常驻放行 IP

收益模型 SHALL 把 `weekly_flat` 与 `hold_through` 作为并列分支计算，不得写死其一。

### D2c. swap 多日计提方向是二值未知，摆动幅度大于点差之争

原 design 用「rate 是否为 3 倍」判定多日计提是**概念混淆**：
`long_rate` 是年化率，覆盖多天应体现在**扣款金额**（coverage_days）上，不在 rate 上。
US500S 的 `-0.1395 = 3 × -0.0465` 恰说明 US500S 与 XAUS 的字段口径不同。

- 若周五 21:05Z 一次收 3 天 → 周末平仓躲掉全部三天，swap 系数 = **4/7**
- 若周一 21:05Z 追补 Sat/Sun → 实付 **6/7**，成本多 `5.72% × 2/7 = +1.63%/年`

**这一个二值问题的摆动幅度大于全部点差争论，必须用 $5 探针仓跨一个周末实测。**

### D3. 双腿执行必须是带持久化状态机的事务
顺序写死为**先 swap 后永续**（受限腿先做、可回滚的腿后做）。
状态机：`FLAT → LEG1_SUBMITTED → LEG1_CONFIRMED → LEG2_SUBMITTED → HEDGED → EXITING / INCIDENT`。

- 每次下单前写入意图日志（write-ahead journal）+ 幂等键。
- 明确区分「确定拒绝」与「结果未知」。**结果未知时禁止重试下单**，
  只允许轮询 `/positions` + `/transfers` 交叉对账。
- 回滚失败 → 进入 `INCIDENT`，停止全部新开仓 + 最高级告警 + 人工介入。
- 重启必须从持久化状态与交易所实仓恢复。
- 「全程保持两腿名义相等」对顺序下单不可实现，改为
  **「临时净 delta 不超过硬上限，且必须在限定秒数内恢复」**。

### D4. 新建独立模块，不复用 HedgeEngine / RiskManager
三个硬理由：
1. **语义相反会杀人**：`engine/risk.py:63` 把「任一腿数据不可得」判为 `FLATTEN`
   （平掉两腿）。本结构里「swap 腿不可交易」是**每天都会发生的正常状态**；
   套用现有风控，休市时它会去平仓，而只能平掉永续腿，
   **正好留下裸 swap 腿过周末**——恰是最怕的后果。
2. **爆炸半径**：`HedgeEngine` 被 `tools/run_lighter_hedge.py`（实盘在跑）、
   `timed_volume/strategy.py`、`grid/grid_engine.py` 共用，改它是拿在跑的钱冒险。
3. **模型不匹配**：现有引擎是 primary/hedge 两个不同 adapter、hedge 跟随再平衡；
   本结构是同一 client、同一底层、两腿对等、同开同关，外加时段与 isolated 约束。

**可复用**：`tools/hedge_gold.py` 的模式（顺序开腿 + `reduce_only` 回滚 +
容忍 `/positions` 最终一致 + 硬名义上限 `MAX_NOTIONAL`）；把「时段判定」
「净 carry 计算」「isolated 强平距离」写成 `engine/` 下的纯函数便于单测。
**不复用**「RFQ ID 等于已全量成交」的假设。

### D5. 探针仓取代纸面采样作为上钱判据
`XAUS min_qty = 0.00003` 盎司 ≈ $0.13。一笔 $5 级探针仓可**一次性同时验证**：
swap 资金费结算记录形态、isolated 实际强平价、多日计提规则、OI 积分是否双计、
开市后能否成交。纸面采样这五条一条都验不了。
纸面采样仍要跑，但用途是**积累费率分布**（放大决策需 30 天、覆盖 4 个周末），
不是上钱门槛。

### D6. 所有仓位查询强制精确匹配
`adapters/variational_client.py:388` 的 `_position_matches_underlying` 默认
`exact=False` 走子串匹配，`get_position("XAU")` 会命中 XAUS 持仓。
全部调用点无一传 `exact=True`（含 `engine/hedge_engine.py:132/139`）。
本结构恰好同账户同时持有 XAU 与 XAUS，必撞。
另：`get_liquidation_info`（`:472`）写死 `maint=0.1` 并用账户权益自算，
对 isolated 腿**结构性错误**（会把账户权益算进 isolated 桶）。
改为直接读 API 返回的 `estimated_liquidation_price`。

## 四、已裁决的原开放问题

1. **OI 积分是否两腿独立计数** → 不为它做任何设计让步，不为它单独开仓、不因它放大规模。
   在 D5 探针仓中顺带观测。
2. **积分窗口只剩约 26 天** → **完全剔除出决策模型**，仅作信息展示。
   carry 必须独立站得住，站不住就不做。
3. **周末保证金水位** → 原问题问错了对象。v1 周末不持仓；持仓过周末的前置条件见 D2。
   永续腿不需要专门垫（它是全仓）。
4. **阈值** → 原「入场 8% / 退出 2% / 最短持仓 7 天」**三条全部作废**：
   - `min_hold_days = 7` 是**硬错误**：周末平仓下最大持仓 = 周日 22:00Z→周五 20:30Z
     = **4 天 22.5 小时**，该规则**永不可达**。更危险的是原 spec 对「硬性退出」的枚举
     不含周末平仓，照字面实现会**拒绝周五平仓、把 isolated 腿裸留 49 小时**——
     恰是 D2/D4 想避免的后果。**删除，改为决策层 `min_commit_cycles = 3`。**
   - 8% 是拍的，不是从成本模型与政策推导的（碰巧落在合理区间也是运气）。
   - **阈值不得用「净 carry」表达**（它隐藏了政策交互），改为对扣除全部摩擦后的
     实际年化收益 R 设阈值，政策作为 R 的输入：
     ```
     weekly_flat:  R = f_perp × 0.705 − f_swap × (4/7) − 52c
     hold_through: R = f_perp − f_swap − n_rebalance × c
     ```
   - 建议：入场 **7 日中位 R ≥ 6%/年 且 R ≥ 3 × 年化摩擦**；
     退出 **R ≤ 0 持续 24 小时**；硬退出 **f_perp < f_swap 连续 3 期**。
   - **豁免（MUST）**：周末平仓 / 单腿失衡 / ADL / kill switch / 地区封锁
     **无条件豁免一切持仓期约束**。
5. **引擎** → 新建模块，见 D4。
6. **IP 限制与部署** → **这是提案能否成立的前置条件**。若开平仓必须人工在放行 IP 执行，
   则「休市前自动平仓 / 单腿爆仓后自动平另一腿」等时间敏感风控在运维上不存在。
   二选一：(a) 策略进程整体常驻放行 IP（含 cookie 自愈与掉线告警），才允许持仓；
   (b) 承认这是人工看盘策略，只在人在场时持仓。
   **不接受「代码写了但要人手动跑风控」**——35.5 小时无声停摆事故就是这么来的。
