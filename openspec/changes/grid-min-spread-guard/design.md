# 设计：网格挂单的最小价差保护

## 故障复盘

2026-08-19 13:39:33 Lighter 做市以 `--spacing 0.0005` 启动，13:41:01 回滚。

```
13:39:46 格22148CANCELLED重挂：SELL 0.004666@64295(格22148) → id=244
13:39:48 格22148 订单 244 终态=CANCELLED 且无成交，准备原格 SELL 重挂
13:39:48 格22148CANCELLED重挂：SELL 0.004666@64295(格22148) → id=246
13:40:08 挂单失败 格22148CANCELLED重挂：(429) Too Many Requests
```

当时价格 64,240，格距 $32，最内侧卖单 64,263 距现价仅 $23。post_only 单一旦
会 cross spread 就被交易所拒绝——这是 post-only 的设计语义，不是异常。

引擎的处理逻辑是「终态 CANCELLED 且无成交 → 原格重挂」，对过期/被动撤单是
正确的，但对 post-only 冲突就是**无限重试**：价差不会因为重挂而变窄。

## 关键决策

### 1. 跳过该格，不调整价格

落在价差内时**不下单**，等下一轮价格移动后再试。

不采用「把价格推到价差外」的方案：网格的格位价格由 `_level_price(level)` 几何
生成，是闭环配对的基准；挪价会让翻单价与原格不匹配，破坏闭环语义和 PnL 归因。
宁可少挂一格。

### 2. 每轮取一次盘口，缓存复用

Lighter 限速 **40 requests per 60 second**（已实测触发）。每轮要挂 20 个单，
若每单查一次盘口，仅此一项就 20 次请求，必然超限。

盘口在 `run_once` 开头随行情一并取，存入本轮缓存，所有挂单校验复用同一份快照。
本轮内盘口可能变化，但价差量级不会突变，快照足够。

### 3. 读取失败必须降级放行

盘口读取失败（超时、接口异常、返回空）时**放行挂单**，退回当前行为。

理由：这是保护性改动，不能自己变成新的故障源。Extended 网格正处 4 周观察期
（剩 25 天），任何让它停止挂单的新失败路径都会污染判据。宁可漏保护，不可误阻断。

### 4. 缓冲比例的默认值必须保证现有行为不变

业界经验是在价差边缘留 0.1~0.3% 缓冲。但我们的格距本身只有 0.0986%，若缓冲
按价格比例取 0.1% 会把所有格挡掉。

因此缓冲定义为**相对价差的倍数**而非相对价格的比例，默认值取保守值，确保
Extended 现行 0.0986% 格距下 `spread × 缓冲倍数 < 格距`，即从不触发。
该默认值须由测试固定。

### 5. CANCELLED 退避是第二道防线

即使有事前校验，仍可能因盘口在下单瞬间变化而被拒。故对「终态 CANCELLED 且
无成交」的格增加退避：同一格连续被撤达到阈值后，暂停重挂若干轮。

这道防线与事前校验独立——事前校验依赖盘口快照可能过期，退避则不依赖任何外部
数据，是兜底。今天的 42 次重挂只要有退避就不会发生。

## 接口设计

两个适配器各新增一个方法，返回 `(best_bid, best_ask)`。引擎只依赖这个统一签名，
不感知交易所差异——与设计文档既有的「引擎解耦」方向一致。

Lighter 侧注意：`/api/v1/candlesticks` 实测 403，但 orderbook 端点可用性需在
实现时验证；若不可用，需退回用 `get_mark_price` 与 tick_size 估算，或直接让
该能力对 Lighter 降级为不启用（此时退避防线仍然有效）。

## 不做

- 不引入动态格距（随波动率/敞口自适应）——那是独立的策略变更，须单独提案。
- 不改库存上限语义、不改 reduce-only 归属路径。
- 不为此调整任何现行实盘参数；缩格距是本变更上线**之后**的独立决定。
